# QA_AUDIT — инвентаризация приложения

Дата: 22.10.2026 · ветка `claude/qa-audit` · среда: локальная (Node 22, PostgreSQL 16, Tesseract 5.3.4 rus/kir/eng, poppler, Chromium/Playwright).
Все проверки создания, изменения и удаления выполнялись на тестовой БД `construction_registry_test` (автотесты) и на отдельных
тестовых проектах `QA-E2E-*` с синтетическими данными в локальной БД разработки (браузерные сценарии). Реальные документы компании не использовались.

## 4. Основные пользовательские сценарии

1. Вход → создание проекта → импорт сметы → сопоставление → черновик версии → утверждение → реестр.
2. Обновление выполнения (объём/%) с датой и комментарием; массовое обновление из Excel; подтверждение превышения.
3. Договор: загрузка файла с извлечением реквизитов или ручной ввод → проверка → «действует» → распределение на статьи → подтверждение.
4. АВР по фото: съёмка/галерея/PDF → предобработка и OCR → проверка оператором (подсветка, уверенность, сопоставление) → создание АВР (черновик/на согласовании) → подписание с датой.
5. 1С: загрузка CSV/XLSX → сопоставление → предпросмотр (новые/дубли) → подтверждение → классификация (затраты на статью/договор, платёж → оплата).
6. Проблемы: автоматическая проверка, устранение данными или исключение с обоснованием.
7. Отчёты и расшифровки, экспорт XLSX/PDF, состояние на дату.
8. Администрирование: пользователи, роли, участники проекта, отзыв доступа, журнал.

## 5. Роли по умолчанию

Администратор, Руководитель проекта, ПТО, Финансы/бухгалтерия, Проверяющий, Наблюдатель (`src/lib/permissions.ts`); 21 право.
Доступ выдаётся на проект; нельзя выдать роль с правами выше собственных.

## 6. Расчёты (единый модуль `src/lib/calc`)

Плановая стоимость, стоимость выполненного, готовность (с ограничением и превышением), остатки, договорное покрытие,
принято по АВР (эффективный статус на дату, корректировки), затраты 1С (только подтверждённые), отклонение, прогноз,
сверка «выполнено − АВР», уровни строки, лимиты договора и АВР, арифметика АВР (допуск 1,00).

## 7. Интеграции и внешние сервисы

Нет. Распознавание выполняется локально (Tesseract). Интеграций с Google Drive, 1С (онлайн), почтой нет. Платные сервисы не подключались.

## 8. Чем проверялось

| Средство | Что |
|---|---|
| `npx tsc --noEmit`, `npm run lint` | типы и линтер |
| `npm run build` + `npm run start` | production-сборка и сервер |
| Vitest, 13 файлов, 109 тестов (3 прогона подряд без сбоев) | расчёты, импорт, OCR (синтетические сканы/фото), интеграция на тестовой БД, права, конкурентность, журнал |
| Playwright: `full.mjs` (24 шага) | сквозной сценарий пользователя в production-сборке |
| Playwright: `neg.mjs` (13 проверок) | негативные сценарии в браузере |
| Playwright: `crawl.mjs` | обход 35 страниц + 28 экспортов, ошибки консоли |
| Playwright: `mobile.mjs` | горизонтальная прокрутка 13 страниц при 390/768/1280 px |
| `scripts/backup.sh` + `scripts/restore.sh` | копия и восстановление во временную БД со сверкой |
| `npm audit --omit=dev` | уязвимости зависимостей |

Браузерные сценарии сохранены в `qa/e2e` (запуск — `qa/e2e/README.md`); в CI они пока не подключены.

Дефекты и результаты — в `QA_FINAL_REPORT.md` и `qa/findings.md`.
