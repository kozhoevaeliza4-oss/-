# Реестр строительных работ и контроль себестоимости

Веб-приложение для строительной компании: объединяет смету, договоры, физическое выполнение, АВР (в том числе
распознанные по фотографии) и данные 1С на уровне каждой статьи работ. Приоритеты: **точность расчётов и достоверность данных** →
удобство ПТО и финансов → автоматизация.

Результаты аудита и тестирования: [`QA_FINAL_REPORT.md`](QA_FINAL_REPORT.md), инвентаризация — [`QA_AUDIT.md`](QA_AUDIT.md).

## Стек

Next.js 15 (App Router, Server Actions) · React 19 · TypeScript · Tailwind CSS · PostgreSQL 16 · Prisma 6 ·
exceljs · pdfkit (шрифты DejaVu в `assets/fonts`) · sharp · decimal.js · zod · Vitest.
Системные утилиты для распознавания: Tesseract 5 с языками rus, kir, eng; poppler-utils (pdftoppm, pdftotext); libheif (heif-convert, для HEIC).

Внешних сервисов нет: документы не отправляются во внешние AI/OCR-сервисы, онлайн-интеграций с 1С и облачными дисками нет.

## Запуск

Требуется Node.js 20+ (проверено на 22), PostgreSQL 14+ (проверено на 16) и утилиты распознавания (см. «Стек»).

```bash
cp .env.example .env               # задайте DATABASE_URL и пароль первого администратора
docker compose up -d db            # или используйте свою PostgreSQL
sudo apt install tesseract-ocr tesseract-ocr-rus tesseract-ocr-kir tesseract-ocr-eng poppler-utils libheif-examples
npm install
npm run db:deploy                  # применить миграции (для разработки: npm run db:migrate)
npm run db:seed                    # роли по умолчанию + администратор из SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD
npm run db:demo                    # (необязательно) демо-проект с вымышленными данными и демо-пользователями
npm run dev                        # http://localhost:3000
```

Продакшен: `npm run build && npm run start` за HTTPS-прокси. Не запускайте `next dev` в каталоге с production-сборкой — он перезаписывает `.next`.

Docker: `docker build -t construction-registry .` и запуск с `DATABASE_URL`, томом для `/data/storage` и HTTPS-прокси перед контейнером;
после первого запуска — `docker exec <контейнер> npm run db:seed`. (Сборка образа в среде аудита не проверялась — см. отчёт.)

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DATABASE_URL` | да | строка подключения PostgreSQL |
| `STORAGE_DIR` | нет (`./storage`) | приватный каталог документов, вне `public/` |
| `MAX_UPLOAD_MB` | нет (25) | максимальный размер загружаемого файла |
| `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` | для `db:seed` | первый администратор |
| `COOKIE_SECURE` | нет (true в продакшене) | cookie только по HTTPS; `false` — только для внутренней сети без TLS |
| `APP_TIMEZONE` | нет (`Asia/Bishkek`) | часовой пояс отображения даты и времени |
| `TESSERACT_PATH`, `OCR_LANGUAGES`, `OCR_PSM`, `OMP_THREAD_LIMIT` | нет | путь к tesseract, языки (`rus+kir+eng`), режим разметки (6), потоки (2) |
| `DEMO_PASSWORD` | нет | пароль демо-пользователей для `db:demo` |
| `TEST_DATABASE_URL` | для тестов | тестовая БД; имя обязано оканчиваться на `_test` |

Секреты в репозитории не хранятся; `.env` исключён из git.

### Проверки

### Резервное копирование и восстановление

```bash
# копия: дамп БД (pg_dump, формат custom) + архив хранилища документов
DATABASE_URL=... STORAGE_DIR=./storage BACKUP_DIR=./backups scripts/backup.sh

# восстановление в ПУСТУЮ БД и пустой каталог (иначе скрипт остановится; принудительно — FORCE=1)
RESTORE_DATABASE_URL=postgresql://user:pass@host:5432/new_db STORAGE_DIR=/path/to/storage \
  scripts/restore.sh backups/db-YYYYMMDD-HHMMSS.dump backups/storage-YYYYMMDD-HHMMSS.tar.gz
```

Порядок восстановления: остановить приложение → восстановить в новую БД и новый каталог → проверить данные (число проектов,
документов, последние записи журнала) → переключить `DATABASE_URL`/`STORAGE_DIR` → запустить. БД и файлы копируются вместе —
документы без записей БД и наоборот не имеют смысла. Копии запускайте по расписанию и храните вне сервера.
Процедура проверена при аудите восстановлением во временную БД со сверкой записей и побайтной сверкой файлов.

### Схема БД

Иерархия: **Проект** → Корпус (`ConstructionObject`) → Этап (`ConstructionStage`) → Раздел сметы (`EstimateSection`) → **Статья работ (`WorkItem`)**.
Статья имеет стабильный идентификатор; плановые значения хранятся по версиям сметы, поэтому договоры, факт и история не теряются при новой редакции.

| Группа | Модели |
|---|---|
| Доступ | `User`, `Session` (хэш токена), `Role` (права), `ProjectMember` (роль в проекте) |
| Смета | `EstimateVersion` (черновик / действующая / заменённая / отклонённая, первоначальная), `EstimateLine` (строка версии → статья), `EstimateSection` |
| Выполнение | `WorkProgressRecord` — неизменяемые записи накопленного итога на дату, с автором, комментарием, источником |
| Договоры | `Contractor`, `Contract` (статус действительности и подписания), `ContractAmendment`, `ContractWorkAllocation` (распределение по статьям, статус подтверждения) |
| АВР | `Act` (статус, дата подписания, корректировка), `ActLine`, `ActLineAllocation` (строка → статьи) |
| Распознавание | `ActRecognition` (статус, черновик, проверки), `ActRecognitionPage` (исходная и подготовленная страница, OCR) |
| 1С | `AccountingImport`, `AccountingTransaction` (отпечаток, классификация, категория), `ClassificationRule`, `TransactionAllocation`, `Payment` |
| Файлы и импорт | `Document` (путь в хранилище, SHA-256), `ImportJob` (сопоставление, предпросмотр, статус), `ExtractedField` |
| Контроль | `AuditLog` (до/после), `Issue`, `IssueEvent` |

Денежные суммы — `Decimal(18,2)`, объёмы и цены — `Decimal(18,4)`, проценты — `Decimal(9,4)`; отсутствие значения хранится как `NULL`, а не 0.

### Импорт сметы

1. Файл сохраняется в приватное хранилище (вне `public/`), проверяются размер, расширение и сигнатура, повторная загрузка того же файла блокируется без явной отметки.
2. Система предлагает лист, строку заголовков и сопоставление столбцов; разделы определяются из строк «Раздел N. …» или из столбца.
3. Предпросмотр показывает ошибки (не число, нет наименования, дубликат ключа) и предупреждения (нет объёма/стоимости, итог ≠ объём × цена, отрицательные значения), служебные и итоговые строки, сверку с итогом файла.
4. Подтверждение создаёт **черновик версии** — реестр не меняется.
5. Утверждение (право `estimate.approve`) показывает сравнение с действующей версией, связывает строки со статьями по ключу, сохраняет предыдущую версию как историю. Первая утверждённая версия — первоначальная смета.

Ключ сопоставления статей между версиями (выбирается при импорте): корпус + раздел + код + наименование (по умолчанию, безопасно),
корпус + раздел + код, или корпус + раздел + № п/п. Автоматического «нечёткого» объединения нет.

## Принятые решения по неоднозначным правилам

Выбрано безопасное поведение по умолчанию; всё можно изменить после согласования.

1. **Плановая стоимость строки** = итог из исходной сметы; если итога нет — объём × цена. Расхождение > 1 ед. валюты показывается предупреждением, исходные значения не пересчитываются.
2. **Стоимость выполненного** = факт × плановая цена; если в смете нет цены — стоимость / объём (с пометкой «производная цена»). Для работ «в процентах» — плановая стоимость × %.
3. **Превышение объёма**: исходный факт и превышение всегда хранятся и показываются. Готовность выше 100 % и стоимость превышения входят в показатели только после подтверждения пользователем с правом `progress.confirmOverrun`; до этого стоимость превышения показывается отдельно, статья — красная.
4. **Договорное покрытие**: статья покрыта, если есть **подтверждённое** распределение на договор в статусе «действует» **или «завершён»** (завершённый договор покрывал работу). Неподтверждённые распределения, договоры «на проверке», «требует уточнения» и «расторгнут» покрытия не дают. Покрытие считается по плановой стоимости статьи; если договоры покрывают меньший объём — предупреждение «частичное покрытие», но статья считается покрытой (уточнить).
5. **Статьи, добавленные вручную**, не имеют плановой стоимости и не входят в общий объём сметы, пока не появятся в утверждённой версии.
6. **Статьи, исключённые новой версией сметы**, остаются в реестре (со своей историей) с пометкой «нет в действующей смете» и не входят в общий объём.
7. **Затраты 1С** до подтверждения методики (флаг в «Структура и настройки») называются «Импортированные затраты по 1С», а отклонения — предварительными. В затраты статьи входят только подтверждённо классифицированные операции.
8. **Оплаты** привязываются к договорам; на уровне статьи без явного распределения не показываются.
9. **Прогноз** рассчитывается только при подтверждённой модели и введённом прогнозе остатка; иначе «Недостаточно данных».
10. **Валюты** не смешиваются: суммы в валюте, отличной от валюты проекта, исключаются из сумм с предупреждением (курсы не реализованы).
11. **Готовность этапа** на панели взвешена по плановой стоимости: Σ стоимости выполненного / Σ плановой стоимости; статьи без внесённого факта не входят в выполненное, их число показывается.
12. **Выполнение** вводится накопленным итогом на дату; «текущее» — запись с последней датой фиксации. Записи не изменяются и не удаляются; обязательны дата и комментарий.

## Безопасность

- Пароли — bcrypt; сессии — случайный токен в httpOnly-cookie, в БД только SHA-256 от токена; блокировка после 5 неудачных попыток входа.
- Доступ выдаётся на конкретный проект (роль в проекте); доступ к одному проекту не даёт доступа к другим. Системный администратор видит все.
- Роли настраиваются; нельзя выдать роль с правами выше собственных. Отзыв доступа завершает все сессии сотрудника.
- Права проверяются на сервере в каждом действии и маршруте. Затраты 1С, договоры и АВР удаляются из ответа сервера (реестр, экспорт,
  карточка, панель, отчёты, расшифровки), если у роли нет `accounting.view`, `contract.view` или `act.view`.
- Файлы отдаются только через `/api/documents/:id` с проверкой права `document.download`; загрузка — лимит размера, белый список расширений, проверка сигнатуры.
- Заголовки: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `Permissions-Policy` (камера только для приложения).
- Журнал действий: входы, загрузки, утверждения, изменения, экспорт, скачивание документов (секретные поля не логируются).

## Ограничения

- Распознавание АВР рассчитано на печатные формы КС-2 хорошего качества; рукописный текст, сильные блики и сложные таблицы требуют ручной проверки
  (оператор подтверждает каждую строку). Качество на реальных актах компании не измерялось — нужны обезличенные примеры.
- Извлечение реквизитов договоров — по шаблонам; нетиповые договоры заполняются вручную.
- Курсы валют не реализованы: суммы в другой валюте не складываются с валютой проекта.
- Очередь распознавания и блокировка перебора паролей работают в памяти одного процесса — при нескольких экземплярах приложения нужен общий механизм.
- Импорт `.xls` (старый формат Excel) не поддерживается — файл нужно пересохранить в `.xlsx`.
- Полный список рисков и требований для эксплуатации — в `QA_FINAL_REPORT.md`.
